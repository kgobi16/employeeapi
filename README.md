# Employee API

A RESTful CRUD API for managing employees, built with Spring Boot.

## Tech stack

- Java 17
- Spring Boot 4.1.0 (Spring Web, Spring Data JPA, Validation)
- H2 in-memory database
- Maven (wrapper included)
- JUnit 5 / Mockito / MockMvc for tests

## Getting started

### Prerequisites

- Java 17 or higher on your `PATH` (`JAVA_HOME` set accordingly)
- No local database needed — H2 runs in-memory

### Run the application

```bash
./mvnw spring-boot:run
```

The API starts on `http://localhost:8080`. The H2 console is available at
`http://localhost:8080/h2-console` (JDBC URL: `jdbc:h2:mem:employeedb`, user: `superadmin`, no password).

### Run the tests

```bash
./mvnw test
```

## API endpoints

| Method | Endpoint              | Description           | Success response |
|--------|------------------------|------------------------|-------------------|
| POST   | `/api/employees`       | Create an employee     | `201 Created`     |
| GET    | `/api/employees`       | List all employees     | `200 OK`          |
| GET    | `/api/employees/{id}`  | Get an employee by ID  | `200 OK`          |
| PUT    | `/api/employees/{id}`  | Update an employee     | `200 OK`          |
| DELETE | `/api/employees/{id}`  | Delete an employee     | `204 No Content`  |

### Employee fields

| Field         | Type       | Constraints                              |
|---------------|------------|-------------------------------------------|
| `id`          | Long       | Generated by the database                 |
| `name`        | String     | Required, must not be blank               |
| `email`       | String     | Required, valid format, unique            |
| `department`  | String     | Required, must not be blank               |
| `salary`      | BigDecimal | Required, must be greater than zero       |
| `joiningDate` | LocalDate  | Required, cannot be in the future         |

## Sample requests

Create an employee:

```bash
curl -i -X POST http://localhost:8080/api/employees \
  -H "Content-Type: application/json" \
  -d '{"name":"Thabo Nkosi","email":"thabo@example.com","department":"Engineering","salary":75000,"joiningDate":"2024-01-15"}'
```

Get an employee by ID:

```bash
curl -i http://localhost:8080/api/employees/1
```

Update an employee:

```bash
curl -i -X PUT http://localhost:8080/api/employees/1 \
  -H "Content-Type: application/json" \
  -d '{"name":"Thabo Nkosi","email":"thabo@example.com","department":"Platform","salary":82000,"joiningDate":"2024-01-15"}'
```

Delete an employee:

```bash
curl -i -X DELETE http://localhost:8080/api/employees/1
```

## Error responses

All errors are returned as a consistent JSON body via a centralized
`@RestControllerAdvice` (`GlobalExceptionHandler`):

```json
{
  "timestamp": "2026-08-20T10:15:30",
  "status": 404,
  "error": "Not Found",
  "message": "Employee with id 99 not found.",
  "path": "/api/employees/99"
}
```

Validation failures additionally include a `validationErrors` map with one
entry per invalid field.

| Scenario                | Status | Cause                                   |
|--------------------------|--------|------------------------------------------|
| Employee created         | 201    | New resource created                    |
| Employee retrieved/updated | 200  | Request succeeded                       |
| Employee deleted         | 204    | Succeeded, nothing to return            |
| Invalid request data     | 400    | Bean Validation failed                  |
| Employee not found       | 404    | Requested resource does not exist       |
| Duplicate email          | 409    | Email already in use by another employee|
| Unexpected error         | 500    | Unhandled exception                     |
